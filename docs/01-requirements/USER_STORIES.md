# 文具商城 MVP — 用户旅程、原子故事与 BDD 验收清单

> 版本：v3.0 · 日期：2026-10-29（合并自 v2.0 user-journey-and-stories + v1.0 USER_STORIES）
> 依据：平时作业《商城系统》需求文档（严格对齐）
> 技术栈：Vue 3 + Vite + Axios 前端 · Java 17 + Spring Boot 3 + MyBatis 后端 · MySQL 8
> 格式约定：用户故事用 `As a… I want to… So that…`；验收场景用 Gherkin Given-When-Then；**Then 断言同时包含页面反馈 + 数据库最终状态**

---

## 0. 角色定义

| 角色 | 来源 | 能做的事 | 明确不能做的事 |
|------|------|----------|----------------|
| **游客** | 未登录 | 浏览首页、分类、商品详情；注册；登录 | 加购物车、下单、看订单、评价 |
| **普通用户** | 自行注册（只能注册成普通用户） | 加购物车、下单、模拟付款、看自己的订单、**取消待支付订单**、**确认收货**、评价、登出 | 访问后台；看别人的订单 |
| **管理员** | 数据库预置（固定 1 个） | 登录后台、查看全部订单、**标记发货**、新增商品、编辑商品、上架、下架 | **下单购物** |

## 1. 端到端用户旅程地图

### 1.1 游客旅程

```
  打开商城首页              浏览分类 / 商品              被拦截 → 注册/登录
┌───────────────────┐  ┌───────────────────┐  ┌────────────────────┐
│ 站名 + 导航        │  │ 一级分类入口        │  │ 点击"加入购物车"   │
│ 分类入口           │→│ 二级分类 + 商品列表  │→│ 或"立即购买"       │
│ 推荐商品区 3~8 件   │  │ 商品详情（价格/库存）│  │ → 跳转注册/登录页   │
└───────────────────┘  └───────────────────┘  └────────────────────┘
```

### 1.2 普通用户旅程（前台主链路）

```
  登录          选购          加购          勾选结算         模拟付款       订单态可做的操作         评价
┌────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────────────────┐  ┌──────────┐
│ 登录   │→│ 分类浏览   │→│ 加入购物车│→│ 勾选若干  │→│ 点"模拟付款"│→│ 待支付 → 取消        │  │ 已完成   │
│        │  │ 商品详情   │  │ 改/删/清空│  │ 行生成订单│  │ 状态=已支付 │  │ 已支付 → 等管理员发货 │→│ 订单可评 │
└────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │ 已发货 → 确认收货     │  └──────────┘
                                                                     │ 已完成 → 评价          │
                                                                     │ 已取消 → 终态          │
                                                                     └─────────────────────┘
```

**订单状态机（5 个状态，作业规定）：**

```
                  [用户模拟付款]
      待支付 ────────────────────► 已支付
         │                           │
         │[用户取消]                  │[管理员标记发货]
         ▼                           ▼
      已取消（终态）              已发货
                                     │
                                     │[用户确认收货]
                                     ▼
                                  已完成（终态）

  规则：
  - 只有"待支付"可以取消，取消时库存回补
  - "已完成"和"已取消"是终态，谁都不能改
  - "已支付"不能确认收货，必须等管理员标记发货后才能操作
```

**关键业务边界（作业明确要求）：**

| # | 边界场景 | 系统行为 |
|---|----------|----------|
| ① | 加购/下单超库存 | **整单失败**，不产生半个订单；扣库存、写订单、写明细必须在**一个事务**里 |
| ② | 下架商品拦截 | 不出现在前台任何列表；不能加购物车；购物车里已有旧记录不能结算 |
| ③ | 重复评价拦截 | 同一订单同一商品只能评价一次，后端拒绝重复提交 |
| ④ | 订单金额可信度 | **由服务端按当时商品价格重新计算**，前端传来的金额不采信 |
| ⑤ | 价格快照 | 订单明细里存**下单当时的商品名称和单价**，之后改价格不影响历史订单 |
| ⑥ | 越权拦截 | 普通用户访问后台 / 别人的订单，**后端拒绝**（不是只靠前端隐藏） |
| ⑦ | 状态不允许 | 非终态/不符合流转条件的操作后端拒绝 |

### 1.3 管理员旅程（后台）

```
  登录后台            商品管理                 订单管理
┌──────────┐  ┌────────────────────┐  ┌────────────────────┐
│ 预置账号   │  │ 列表（含已下架，     │  │ 全部用户的订单列表  │
│ 密码登录   │→│  状态可区分，        │  │ 按状态筛选          │
└──────────┘  │  按分类筛选）        │  │ 查看完整商品明细    │
      │       │ 新增 / 编辑商品      │  │ 【标记发货】        │
      │       │ 上架 / 下架切换       │  │ 不做退款 / 不删订单 │
      │       └────────────────────┘  └────────────────────┘
      │
      ▼
  硬约束：管理员**不能下单**
  - 前端隐藏购物车/下单入口
  - 后端对订单相关接口返回无权限状态码
```

## 2. 核心原子化用户故事 + 验收标准 + BDD 场景

> 全部符合 **INVEST 原则**；每故事 = As a/I want/So that + 验收条件 + 1 主干 + N 边界 Given-When-Then

---

### US-01 · 注册、登录、登出

**As a** 游客  
**I want to** 注册一个用户名唯一的普通用户账号，并用它登录商城、随时登出  
**So that** 我获得可以购物的身份，且退出后旧登录态立即失效

**验收条件：**
1. 注册字段：用户名（唯一）、密码；提交合法数据后系统创建用户、密码**不明文存库**（哈希 + 盐）
2. 重复用户名注册时，后端拒绝并返回"该用户名已被占用"
3. 登录成功后写入登录态，**刷新页面登录态不丢**；登出后该登录态立即被后端拒绝
4. 注册只能创建**普通用户**，注册页面不出现"角色"选择项
5. 管理员账号由数据库初始化脚本预置，前端无管理员注册入口

**BDD 场景：**

#### 主干 US01-01 · 游客成功注册并自动登录

```gherkin
Given 商城数据库中存在初始数据（普通用户 2 个、管理员 1 个、商品 ≥ 12 件）
  And 数据库中没有用户名 "alice" 的记录
When 游客在注册页提交用户名 "alice" 和合法密码 "P@ssw0rd"
Then 页面跳转到商城首页并显示"欢迎，alice"
  And 刷新页面后登录态仍然保持（无需重新登录）
  And 数据库 users 表中新增一条记录：username = 'alice', role = 'USER'
  And 该记录的 password 字段不是明文 "P@ssw0rd"（是哈希值，长度 ≥ 60 字符）
```

#### 边界 US01-02 · 重复用户名注册被拒绝

```gherkin
Given 商城数据库中已存在用户名 "bob"
When 游客在注册页提交用户名 "bob" 和任意密码
Then 页面停留在注册页并显示错误提示"该用户名已被占用"
  And 网络响应状态码为 409（Conflict）
  And 数据库 users 表中 username = 'bob' 的记录条数仍然是 1
```

#### 边界 US01-03 · 登出后旧登录态被后端拒绝

```gherkin
Given 用户 "alice" 已登录，浏览器持有有效 token
Given 用户手动点击"登出"按钮
When 前端用刚才持有的旧 token 再次请求 `/api/cart` 接口
Then 网络响应状态码为 401（Unauthorized）
  And 响应体 message 字段为"登录态已失效"之类的明确提示
  And 页面跳转到登录页
```

#### 边界 US01-04 · 注册表单不出现"管理员"角色选项

```gherkin
Given 游客打开注册页
When 完整渲染注册表单 DOM
Then 表单中不存在任何"角色 / role"选择下拉框或单选按钮
  And 提交注册请求的 payload 中不含 role 字段，或 role 固定为 USER
```

### US-02 · 首页、两级分类、商品浏览

**As a** 任何访客  
**I want to** 在首页看到站名、导航、一级分类入口和推荐商品区，并能通过一级分类 → 二级分类浏览商品，点开看详情  
**So that** 我能按分类找到文具并了解价格、库存和评价

**验收条件：**
1. 首页包含：站名、顶部导航栏、**一级分类入口**（≥3 个）、推荐商品区（3~8 件，来自数据库查询）
2. 商品分类为**两级**：一级分类 ≥3 个，商品挂在**二级分类**下；列表页可按一级分类筛选
3. 商品列表卡片显示：图片、名称、价格、库存数量；**只展示上架商品**
4. 商品详情页展示：名称、价格、所属二级分类、库存、描述、**该商品的评价列表**
5. 已下架商品不出现在列表和分类中；通过直链访问下架商品返回明确提示
6. 分类数据来自数据库，不在前端写死

**BDD 场景：**

#### 主干 US02-01 · 访客通过一级分类 → 二级分类浏览上架商品

```gherkin
Given 数据库中存在一级分类 "文具用品"（id=1）、二级分类 "圆珠笔"（父级 id=1）
  And 存在 3 件上架商品挂在二级分类 "圆珠笔" 下（库存分别为 20、5、0）
  And 存在 1 件下架商品挂在同一二级分类下
When 访客打开商城首页
Then 页面顶部显示站名和导航
  And 页面出现一级分类入口 ≥ 3 个（含"文具用品"）
  And 页面出现推荐商品区，展示 3~8 件商品，全部来自数据库查询
When 访客点击一级分类 "文具用品" 入口
Then 商品列表筛选为"文具用品"下的所有商品
When 访客进一步选择二级分类 "圆珠笔"
Then 列表展示 3 件上架商品（库存为 0 的商品照常显示但库存列值为 0）
  And 下架商品不出现在列表中
  And 数据库 products 表中 id 对应列表中每件商品的 on_shelf 字段均为 1
```

#### 边界 US02-02 · 直链访问下架商品返回明确提示

```gherkin
Given 数据库中存在一件下架商品（id=99, name="已下架钢笔", on_shelf=0）
When 访客通过 URL `/products/99` 直接访问该商品详情页
Then 页面显示"该商品已下架，暂不可购买"之类的明确提示
  And 页面中不存在"加入购物车"按钮
  And 后端接口 `/api/products/99` 返回的数据中 on_shelf = 0
```

#### 边界 US02-03 · 首页推荐商品来自数据库而非前端写死

```gherkin
Given 前端代码库中首页组件不存在任何硬编码的商品名称或商品数组字面量
When 后端数据库把商品 "铅笔盒" 的 name 改成 "大容量铅笔盒 2.0"
Then 刷新前端首页后，推荐商品区该商品名称同步显示为 "大容量铅笔盒 2.0"
```

#### 边界 US02-04 · 商品详情展示评价列表

```gherkin
Given 商品 id=5 存在，且数据库 evaluations 表中存在 3 条指向 product_id=5 的评价
When 访客打开 `/products/5` 详情页
Then 页面底部或侧边出现评价列表区域
  And 每条评价显示评分星级 1~5 和文字内容
  And 评价总数显示与数据库 evaluations 表 product_id=5 的 count 一致
```

### US-03 · 购物车管理

**As a** 普通用户  
**I want to** 把商品加入购物车、同一商品重复加入时只累加数量、可修改数量、删除、清空，并实时看到合计金额  
**So that** 我可以在下单前灵活整理想要购买的文具

**验收条件：**
1. 加购时后端校验：商品是否上架、库存是否足够；**下架商品和库存不足商品被拒绝**
2. 同一商品已在购物车时，再次加购只**累加数量**（不产生重复行）
3. 修改数量时，新数量不能超过当前库存；超量修改被后端拒绝
4. 购物车页面展示每行小计（单价 × 数量）和**合计总金额**
5. 进入结算页前，自动清理购物车里的**下架商品**并提示用户
6. 游客状态下点击加购，跳转登录页并携带返回参数

**BDD 场景：**

#### 主干 US03-01 · 普通用户加购并看到合计金额

```gherkin
Given 已登录的普通用户 "alice"
  And 数据库中商品 A 上架、库存 10、单价 ¥5.00；商品 B 上架、库存 20、单价 ¥10.00
When alice 在商品 A 详情页点击"加入购物车"
Then 购物车出现商品 A 一行，数量 = 1，小计 = ¥5.00
When alice 在商品 B 详情页点击"加入购物车"并修改数量为 2
Then 购物车商品 B 数量 = 2，小计 = ¥20.00
  And 购物车合计金额显示 ¥25.00
  And 数据库 cart_items 表中 user_id=alice 的记录条数 = 2
```

#### 边界 US03-02 · 同一商品重复加购只累加数量

```gherkin
Given 已登录普通用户 "alice"
  And alice 的购物车里已有商品 A（数量 = 1）
  And 商品 A 上架、库存 ≥ 5
When alice 再次在商品 A 详情页点击"加入购物车"
Then 购物车商品 A 数量变为 2（不产生第二条重复记录）
  And 数据库 cart_items 表中 user_id=alice AND product_id=A 的记录条数仍为 1，quantity 字段为 2
```

#### 边界 US03-03 · 下架商品或库存不足商品加购被后端拒绝

```gherkin
Given 已登录普通用户 "alice"
  And 商品 B 已下架（on_shelf=0）
When alice 尝试将商品 B 加入购物车
Then 页面显示错误提示"该商品已下架，无法加入购物车"
  And 网络响应状态码为 400
  And 数据库 cart_items 表中没有新增指向商品 B 的记录
---
Given 已登录普通用户 "alice"
  And 商品 C 上架、库存 = 1
  And alice 已持有商品 C 数量 = 1 在购物车
When alice 尝试把商品 C 再加数量改为 2
Then 页面显示"库存不足，当前仅剩 1 件"
  And 网络响应状态码为 400
  And 数据库 cart_items 中商品 C 的 quantity 仍为 1
```

#### 边界 US03-04 · 结算前自动剔除下架商品

```gherkin
Given 已登录普通用户 "alice"
  And alice 的购物车里有商品 A（上架）和商品 B（已下架，是之前加购后被管理员下架的）
When alice 进入结算页
Then 商品 B 自动从购物车中消失，结算页只显示商品 A
  And 页面顶部弹出提示"已自动移除 1 件已下架商品"
  And 数据库 cart_items 中 product_id=B 的记录被删除
```

#### 边界 US03-05 · 游客点击加购被跳转登录页

```gherkin
Given 访客未登录
When 访客点击任一商品的"加入购物车"按钮
Then 页面跳转到登录页
  And URL query string 中携带 return 参数（如 ?redirect=/products/5）
  And 购物车接口不会被实际调用（或调用被后端返回 401）
```

### US-04 · 结算与模拟付款

**As a** 普通用户  
**I want to** 勾选购物车中的若干行、填一个收货地址文本框，提交后系统自动扣库存、写订单和订单明细，并把订单状态改成已支付  
**So that** 我能完成一次模拟的购物付款闭环

**验收条件：**
1. 勾选购物车中的**任意若干行**结算，不是必须整单结算
2. 下单时填一个**收货地址文本框**（不做地址管理）
3. 后端事务：**扣库存、写订单、写订单明细在同一个事务里**，任一失败全部回滚；**库存不允许负数**
4. 下单总数量超过库存 → **整单失败**，返回不足商品清单，不产生半个订单
5. **订单金额由服务端按下单当时的商品价格重新计算**，前端传来的金额字段不采信
6. 订单明细里**存下单当时的商品名称和单价**（价格快照），之后改商品价格不影响历史订单
7. 模拟付款就是点一下按钮把状态从「待支付」改成「已支付」，**不接真实支付**
8. 订单创建成功后**清空已勾选**的购物车行

**BDD 场景：**

#### 主干 US04-01 · 勾选购物车行结算 → 模拟付款 → 订单已支付

```gherkin
Given 已登录普通用户 "alice"
  And 商品 A 上架、库存 10、单价 ¥5.00；商品 B 上架、库存 20、单价 ¥10.00
  And alice 购物车里有 A×2、B×1
When alice 在结算页勾选 A 和 B 两行
  And 输入收货地址文本框"北京市朝阳区某某路 1 号"
  And 点击"提交订单"
Then 页面跳转到订单详情页，显示订单号
  And 订单状态显示"已支付"
  And 数据库 orders 表新增 1 条：user_id=alice, status='PAID', address='北京市朝阳区某某路 1 号'
  And 数据库 order_items 表新增 2 条，分别对应 A 和 B
  And order_items 中每条的 unit_price 等于下单当时的商品单价（A=5.00, B=10.00）
  And 数据库 products 表中 A 的库存变为 8，B 的库存变为 19
  And 数据库 cart_items 中 alice 勾选的两行被清空（删除）
```

#### 边界 US04-02 · 前端传来的金额不采信（服务端重新计算）

```gherkin
Given 已登录普通用户 "alice"
  And 商品 A 上架、库存 10、单价 ¥5.00
  And alice 购物车里有 A×2
When alice 通过浏览器开发者工具篡改前端提交的订单金额字段为 ¥0.01 后提交
Then 订单成功创建，但数据库 orders 表 total_amount 字段为 ¥10.00（后端重算值）
  And 订单详情页显示总金额 ¥10.00
  And 订单明细中的 A 数量 × 单价 = ¥10.00 与 total_amount 一致
```

#### 边界 US04-03 · 库存不足 → 整单失败 + 事务回滚

```gherkin
  And 数据库 products 表中商品 A 库存仍然 = 1（没有被错误扣减）
```

### US-05 · 我的订单（查看 + 取消 + 确认收货）

**As a** 普通用户  
**I want to** 查看自己所有订单的列表和详情，对待支付订单可以取消，对已发货订单可以确认收货  
**So that** 我知道订单状态并能执行我权限内的操作

**验收条件：**
1. 订单列表显示：订单号、下单时间、商品数量、总金额、当前状态；**按下单时间倒序**
2. 订单详情显示：收货地址、完整商品明细（名称、下单时单价、数量、小计）、状态流转时间线
3. **只有"待支付"状态的订单可以取消**；取消时**库存回补**到对应商品
4. **只有"已发货"状态的订单可以确认收货**；确认后订单状态变为「已完成」（终态）
5. 「已完成」和「已取消」是终态，任何后续操作被后端拒绝
6. 未登录访问订单接口 → 后端返回未登录状态码；普通用户请求**别人的订单号** → 后端拒绝（返回无权限）
7. 订单相关所有接口**后端校验登录态 + 归属权**，不依赖前端隐藏/禁用

**BDD 场景：**

#### 主干 US05-01 · 用户查看自己订单列表和详情

```gherkin
Given 已登录普通用户 "alice"
  And alice 历史上有 3 笔订单（状态分别为 PAID / SHIPPED / COMPLETED）
When alice 打开"我的订单"列表
Then 页面按下单时间倒序展示 3 条
  And 每条显示：订单号、下单时间、商品数量、总金额、当前状态中文标签
When alice 点击 PAID 状态的订单进入详情
Then 详情页展示：收货地址文本、完整商品明细、状态流转时间线（至少显示"下单时间"和"付款时间"）
  And 数据库 orders + order_items 查询结果与页面显示一致
```

#### 边界 US05-02 · 只有"待支付"订单可以取消，取消时库存回补

```gherkin
Given 已登录普通用户 "alice"
  And alice 有一笔"待支付"订单（status='UNPAID'），内含商品 A×2
  And 商品 A 当前库存 = 8
When alice 点击"取消订单"并确认
Then 页面显示"订单已取消"，订单状态变为"已取消"
  And 数据库 orders 表该订单 status 字段变为 'CANCELLED'
```

#### 边界 US05-04 · 只有"已发货"订单可以确认收货

```gherkin
Given 已登录普通用户 "alice"

When alice 点击"确认收货"并确认
Then 页面显示"订单已完成"
```

**So that** 我能维护在售商品目录，卖完的及时下架避免超卖

- ❌ 报表、看板、数据可视化（除作业验收必要的列表视图外）
